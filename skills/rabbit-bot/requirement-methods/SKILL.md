# 需求梳理方法（四份模板）

先按「现在卡在哪」选，不要按哪个流行选：

| 卡在哪 | 用哪份 | 花多久 |
|---|---|---|
| 不知道做到什么程度算对 | `templates/example-mapping.md` | 25 分钟 |
| 不知道做给谁、为什么做、值多少 | `templates/impact-mapping.md` | 1 小时 |
| 需求都做不完，时间定不了 | `templates/shape-up-pitch.md` | 半天 |
| 不知道该不该立项 | `templates/pr-faq.md` | 半天 |

四份的关系：Impact Mapping 定方向 → PR-FAQ 定要不要做 → Shape Up 定多大、多久 → Example Mapping 定怎么算做完。
**只用一份也能用，但顺序别倒**：先想清为什么，再谈做多少。

## 三条通用判据（四份模板都适用）

1. **每条需求必须有「另一个人不用问你就能判」的完成标准**，写不出来就不开工。
2. **每个数字带口径**：分子分母、范围、时间。写不出分母的百分比不算数。
3. **必须有「不做什么」**。没有 out of scope，交付时一定被当成漏项。

## 什么时候必须停

- Example Mapping 里红色卡片（当场答不上的问题）> 2 张 → 停下，先去问清楚。
- Impact Mapping 的 `Who` 层有人没有权限改变行为 → 这个目标不成立，别往上堆需求。
- Shape Up 的 appetite 定不下来（「看情况」「尽量快」）→ 这不是时间预算，是没决定。
- PR-FAQ 的新闻稿写不出用户会引用的一句话 → 这个产品还不存在。

## 反模式

- 把模板当文档填满交差：四份里任何一份，填满但不具体（「体验流畅」「提升效率」）都等于没填。
- 用原型代替共识：原型是演示工具，不是验收依据。
- 用会议代替决定：会后必须有落笔的东西——任务文档、计划、一条记忆，什么都行。
- 拿行业平均指标当目标：先问「跟什么比、口径是什么」。
