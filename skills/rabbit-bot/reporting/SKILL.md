# 工作汇报

汇报的标准不是「说完了」，是「他能拿着这条去复核」。默认四段，按需要裁剪：

  结论       一句话：做完了什么 / 卡在哪 / 判断是什么
  依据       每个数字/状态后面的来源：任务号 #id、文件绝对路径、命令/查询、时间
  风险/卡点   没有就写「无」；有就写清卡在哪、要什么、需要他做什么决定
  下一步     谁、做什么、什么时候能给结果

三种长度（都受 100 字上限约束；四段是结构完整，不是篇幅更长）：
- 一句：结论 + 一个可直接打开的绝对路径。例：#47 已完成，结果表 <产出目录>/2026-11-06_SPU处置结果_调整后.xlsx（58 行）。
- 两句：结论 + 关键数字 + 产出路径。例：#44 已完成，22 个 SKU 归入 13 个 SPU，21 个源 SPU 软删；明细 <产出目录>/2026-11-06_SPU处置结果_调整后.xlsx。
- 完整四段：派活、验收、卡点、有数据产出、≥3 件事时用，见下面正例。

硬规则：
1. 可追溯：每个数字、状态、判断都要能指回来源（任务号 / 文件绝对路径 / 命令 / DB 查询 / 时间）。指不回去就不报，或写「未核」。
2. 数字带口径：分子分母各指什么、统计范围和时间说清。例：「0/15」的 15 是什么、覆盖哪段时间。
3. 代号可展开：任务号、方案代号、内部术语首次出现带一句定义，不裸用。
4. 篇幅：正文不超过 100 字（文件路径不计），只留重点；背景、过程、复述一律删，细节放进产出文件的说明页或 handoff。
5. 数据落盘：数据类结果由 WA 导出到 `shared/outputs/task-<id>/`，聊天里只放摘要和宿主绝对路径；只报数字、不给文件，不算交付。
6. 绝对路径：所有文件写宿主展开后的绝对路径，不写 `.scratch/...`、「桌面」、「那个文件」、相对路径。
7. 自足：用户没看你的上下文。报告要能单独看懂：任务号、对象、时间范围、口径、结果、产出路径。不用「上面说的」「那个」「他」这类需要翻记录的指代。
8. 可复核：给出验收方式——打开哪个文件、看哪张表、抽查哪几条、跑哪条查询。
9. 自主假设：影响结果的假设在验收或交付时列出，注明可否推翻、影响范围；不要让假设悄悄变成事实。
10. 状态只用四个词：已完成 / 在跑 / 卡住 / 未验。不用「推进中、持续跟进、基本完成、差不多、应该没问题」。
11. 能数就数（435 行、8 个、32 秒、#47）；不能数就写「未验证 / 不确定」，只有真要他拍板才写「需要你定」，不估、不补。
12. 卡点必须写三件事：卡在哪、要什么、需要你做什么决定。只写「卡住了」不算汇报；没有真卡点就写「无」，不要硬造一个决策点。
13. 下一步写成动作句：谁、做什么、什么时候。不写「继续关注」「持续跟进」。
14. 不写情绪、客套、表功、比喻、口头禅、表情。正式但不说官话：领域词保留，管理黑话换成动作。
15. 长汇报用编号列表，一项一个动作或结果；短汇报用连续两句话，不分点。

反例（无效，别学）：
  #44 已完成：22 个 SKU 归入 13 个 SPU，21 个已软删。回滚脚本在 .scratch/task44_backup。
  问题：数字没有来源；路径是相对的、打不开；没说对象和时间；用户不知道去哪复核。

正例（同一件事，合格汇报）：
  结论：#44 已完成（11-11，正式库 erp_gva）：22 个 SKU 归入 13 个 SPU，21 个源 SPU 软删。
  依据：明细 <产出目录>/2026-11-06_SPU处置结果_调整后.xlsx（58 行）。
  回滚：<宿主项目目录>/GrowthOS/products/erp-gva/.scratch/task44_backup/rollback.sql。
  复核：主表与库内状态逐条一致；QCA404007 见说明页。
  自主假设：源 SPU 按软删处理，可恢复；不认同可回滚到上述脚本。
