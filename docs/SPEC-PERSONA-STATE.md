# SPEC：人格状态（极简版）

> 2026-11-04 二版。一版写了「情绪 × 精力 × 好感度」三状态机 + 分类器 + 衰减任务，
> 看过代码后发现**结构已经在了**，那些全是多余的。这版只改提示词。

---

## 1. 结论先行

「她记得自己上一轮什么心情」这件事，**现在就能跑，只差一句提示词**。不需要新表、不需要分类器、不需要定时任务。

现有闭环（已核实）：

| 环节 | 位置 | 现状 |
|---|---|---|
| 自省产出 `thought` | `core/reflection.ts:172` | 要求「你此刻心里在想什么，一两句话」 |
| `thought` 进下一次自省 | `reflection.ts:159` | `上一次你在想：${prevThought}` 已有 |
| `thought` 进普通聊天 | `app.ts:180` | `你刚才在想：${r.thought}` 已有 |
| 存库 | `reflections.thought` | 已有 |

**问题只有一个**：`thought` 的定义是「在想什么事」，没让它承载「我现在什么状态」。
所以它每次写「他在弄那个任务编排器」，而不是「有点累，但还是想问他一句」。

## 2. 唯一的改动

### 2.1 改 `thought` 的提示词（`core/reflection.ts:172` 附近）

```
现在：
  "thought": "你此刻心里在想什么，一两句话，写具体的，别写空话"

改成：
  "thought": "你此刻的状态和在想的事，一到两句话：先说你此刻的心情和累不累，
              再说你在想什么。写具体的，别写空话"
```

**为什么挤在同一句里**：拆成 `thought` / `mood` 两列的话，两边的语气会打架（想事写得很具体、心情写成「平静」这种空词），还多一个字段、多一处注入。合成一句，她自然会写成「有点累，他今天话比平时少」。

### 2.2 加一行延续提示（`data/sandbox/prompt/system.md`）

```
你的心情和状态是连续的。上一轮在想什么、什么心情，这一轮接着往下走，
不用每次都回到「平静、正常」。
```

**就这两处。** 无表结构改动、无新增 LLM 调用、无新增定时器。

## 3. 砍掉了什么，为什么

| 一版里的东西 | 处置 | 理由 |
|---|---|---|
| `persona_state` 表（情绪/精力/好感度） | **砍** | `thought` 已经在流转，再开一张表是把同一件事存两遍 |
| 分类器（每轮一次轻量调用） | **砍** | 让第二个模型给她的心情打分，会跟她的自述打架；每轮多一次调用也是实打实的成本 |
| 5 分钟衰减任务 | **砍** | 状态每次自省重写，天然覆盖；没有持久数值就没有衰减问题 |
| 7 个情绪枚举 | **砍** | 枚举是给分类器用的。她自己写「有点烦但还行」，比映射到 `annoyed` 准 |
| 不对称影响表 | **砍** | 那是防反馈死循环的。没有数值反馈，就没有循环 |
| 好感度 | **砍** | 它影响长期关系，不是一轮心情；真有需要再单独提 |

一版的复杂度全部来自一个前提：「要把状态变成可计算的数字」。**去掉这个前提，剩下的就是一句提示词。**

## 4. 什么时候才需要升级

只有两种情况值得回头加表（方案 B：`reflections` 加一列 `mood`，约 30 行）：

1. **`thought` 里的状态总被话题挤掉**：跑一周，十条里九条只写事不写心情。那就拆一列，强制它填。
2. **要能查「她这周心情怎么样」**：需要按状态聚合时才值得落库。

这两个都还没发生，先别加。

## 6. 非目标
