## 二、建议先做（成本低，收益立刻能看见）

### 7. 服务端风格闸
**出处**：`dsh-bili-scroll` 养鱼方案（1059★）
**机制**：在她的话发出去之前，代码先过一遍黑名单——「收到」「好的呀」「哈哈哈」纯语气、以及跟最近 20 条重复的，直接拦下来重写或换一条。
**改法**：`src/core/` 加一个 `style-gate.ts`，接在 engine 输出 → 发消息之间。~80 行。
**成本**：半天。零提示词改动，提示词改了它会跟着坏。
**收益**：**套话是她最大的「人机感」来源**，这条不解决，提示词写得再好也白搭。

### 8. 判重表
**出处**：同上（养鱼方案的另一个件）
**机制**：一张 `(话题 hash, 上次发送时间)` 表。同一个梗 / 同一句关心，7 天内不再发。
**改法**：`db.ts` 加表 + 发送前查一次。~50 行。
**成本**：半天。
**收益**：解决「又问我吃饭没有」。她现在的重复是**跨天重复**，提示词管不住，只有代码管得住。

### 9. 她的话加长度上限
**出处**：Super-agent 4.2 节，官方内部硬规定「IM 单次回复不超过 100 词」
**机制**：服务端截断 / 或提示词 + 断言双保险。IM 场景短，长内容进文件。
**改法**：`style-gate.ts` 里一起做。
**成本**：2 小时。
**收益**：她最近几条明显偏长，飞书里读着累。

### 10. 记忆加时间维度
**出处**：Elysian（`supersede` + `valid_from` / `valid_to`）
**机制**：每条记忆标「从什么时候成立 / 什么时候失效」，新记忆顶掉旧的而不是并存。
**改法**：`memories` 表加两列 + 写入时自动 `supersede` 同主题旧条目。
**成本**：1 天（含迁移）。
**收益**：现在「想辞职」和「想升职」会同时活着互相打架。她的记忆是**扁平快照**，没有「以前 vs 现在」。

### 11. 模板变量断言
**出处**：你 10-31 说的四条最佳实践之四（剩下的一半）
**机制**：每个 `{{变量}}` 都断言能从一个 `render()` 调用里取到；漏一个就测试红。
**改法**：`test/template.test.ts` 加一条。~40 行。
**成本**：2 小时。
**收益**：现在只测了「文件在不在、文案有没有」，没测「变量供得上」。下次加新块会踩坑。

## 三、值得试（要动结构，收益明确但不是半天能完）

### 12. 双层：Router / Worker 分开
**出处**：Super-agent 第 2 节。**实验结果**：Super-agent p50 12.4 / p95 15.7 分钟，单 Session + Subagent 的 p95 是 29.5 分钟。
**机制**：Router 只负责「跟我说什么话」，Worker 在独立上下文干活、不直接跟人说话。
**对她**：现在的毛病正是「聊着聊着跑去做别的」——因为一个会话既接话又干活。改成 Router（陪聊 + 分派）+ Worker（干活），她就不会在聊天中途消失。
**改法**：`engine.ts` 拆两套 system prompt + 两个会话 id；Worker 结果回到 Router 再转述。
**成本**：3–5 天，且要改 `messages` 的表结构（区分 router/worker 消息）。
**风险**：她的 90% 时间在陪聊，Worker 用得少——**收益可能低于成本**。建议先用「干活时另起会话」的轻量版试。

### 13. 投机执行
**出处**：Super-agent 3.4 节
**机制**：在还不确定用不用的时候，后台先做。有用就交付，没用就丢。
**对她**：他还没说话时，先按最近话题想好 2 个接法，他开口就能秒回。
**改法**：tide 唤醒时附带一个「预备话题」字段，写进 `handoff`。不需要真起后台会话。
**成本**：2 天。
**收益**：直接改善「冷场」——她不用等到被叫才开始想。

### 14. Watchdog 自检
**出处**：Super-agent 第 6 节
**机制**：主系统之外的独立会话，定时检查「她这几条有没有实质进展 / 有没有跑偏」，异常就修（增删提示词、调触发规则）。
**对她**：现在的 tide 只管「什么时候叫醒」，不管「叫醒之后说得怎么样」。
**改法**：独立 cron + 独立会话，读最近 N 条 + 提示词，产出「哪里说得不好」。
**成本**：2–3 天。
**收益**：**这是唯一能让她自己发现自己变差的机制**。但要小心——自检也容易变成走过场。

### 15. 语境局部性（Inline & Spill 的正式版）
**出处**：Super-agent 3.3 节：「浪费上下文窗口，就是浪费模型的智能」
**机制**：近处信息 Inline 进窗口，远处只留引用按需读。
**对她**：**你今天的提示词路由化已经是手工版**（system.md = Inline，scene-*.md = Spill）。剩下没做的是**话题库**：现在要 `cat INDEX.md` 才知道有哪些块，应该把 9 个块的**一行摘要直接放进主提示词**。
**改法**：`part-topics.md` 里嵌 9 行摘要，不用她先 cat。
**成本**：1 小时。
**收益**：省一次工具往返。**这条最便宜，可以顺手做**。
